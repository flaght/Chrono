# 因子分类与批次目录命名规范

版本：3.0  
日期：2026-09-04

## 1. 核心定义

- `tc001`、`tf001`、`ts001`、`tb001` 是**分类批次目录名**，同时作为该批次下所有因子的**命名空间前缀**。
- 因子统一采用基于批次命名空间的**隐匿代号命名制**：`<批次目录名>_<三位序号>`，例如 `tc001_001.py`、`tf001_001.py`。
- **设计初衷与逻辑保密**：发出的数据和特征列名不能让外部猜测到具体数学算法与 Alpha 逻辑。因此对外输出列名与因子注册名统一使用中性代号，具体的数学逻辑、公式与参数说明严格记录在内部文件头部注释与内部文档中。
- **避免冲突**：每个批次目录内独立自增（从 `001` 开始），通过批次前缀天然隔离，彻底杜绝不同批次之间的命名冲突（如 `tf001_001` 与 `tf002_001` 互不干扰）。

## 2. 批次目录格式

目录名采用：

```text
<因子家族><市场范围><三位批次号>
```

例如 `tc001`、`tc002`、`tf001`、`ts001`、`tb001`、`mc001`。

- 三位数字是同一分类下的代码批次，从 `001` 开始递增。
- 批次号不表达因子公式、参数、周期、优先级或版本。
- 一个批次目录包含多个因子文件。
- 创建新批次不能改变已有因子的名称和输出列。

## 3. 第一个字母：因子家族

| 代码 | 家族 | 适用逻辑 |
| --- | --- | --- |
| `t` | technical | Bar 行情上的技术、量价、动量、波动、趋势和基差等序列因子 |
| `m` | microstructure | Tick、逐笔成交、逐笔委托、订单簿和订单流等微观结构因子 |

新增家族前必须先补充本规范和相应字段契约。

## 4. 第二个字母：市场范围

| 代码 | 范围 | 判断依据 |
| --- | --- | --- |
| `c` | common | 期货和现货都可计算，不依赖某一市场专属字段或语义 |
| `f` | futures | 依赖持仓量、合约结构等期货专属字段或语义 |
| `s` | spot | 依赖现货专属字段或市场机制 |
| `b` | basis | 同时依赖期货和现货对齐数据 |

因此技术与量价因子使用 `tcXXX`、`tfXXX`、`tsXXX`、`tbXXX`；微观结构因子使用 `mcXXX`、`mfXXX`、`msXXX`、`mbXXX`。

## 5. 分类判断

- 只依赖 `open`、`high`、`low`、`close`、`volume`、`value` 的 Bar 因子放入 `tcXXX/`。
- 使用 `openint`、到期日、合约月份等期货专属能力的 Bar 因子放入 `tfXXX/`。
- 只有真正依赖现货专属字段或机制时才放入 `tsXXX/`。
- 同时使用 `future_*` 和 `spot_*` 时放入 `tbXXX/`。
- Tick、逐笔和订单簿因子按相同规则放入 `mc/mf/ms/mb` 对应批次。

分类依据是公式实际字段依赖和语义，不是原始目录、数据文件来源或因子自身名称。因子只在期货数据上运行过，不代表它属于 `tf`。

## 6. 因子文件命名与契约

```text
feature/tc001/tc001_001.py
feature/tc001/tc001_025.py
feature/tf001/tf001_001.py
feature/tb001/tb001_001.py
```

- **四位一体契约**：
  1. 文件名：`<batch>_<seq>.py`（如 `tc001_001.py`）
  2. 注册名 (`FactorSpec.name`)：`"<batch>_<seq>"`（如 `"tc001_001"`）
  3. 计算入口导出名：`<batch>_<seq>_compute`（如 `tc001_001_compute`）
  4. 基础输出列名：`"<batch>_<seq>"`（如 `"tc001_001"`）
- 一个文件只实现一种因子核心逻辑。
- 严禁跨批次借用或在批次内使用具有误导性的外部代号（例如禁止在 `tc` 目录下命名 `tf` 或 `tb`）。
- 参数不同应复用同一个文件；参数化衍生输出可命名为 `tc001_001_5`、`tc001_001_10`。
- 频率不写入分类目录规则，未明确频率时统一使用“周期”。

## 7. 目录结构

```text
feature/
├── tc001/
│   ├── tc001_001.py
│   ├── tc001_025.py
│   └── __init__.py
├── tc002/
├── tf001/
├── ts001/
├── tb001/
├── mc001/
├── mf001/
├── ms001/
├── mb001/
├── utils/
└── __init__.py
```

## 8. 包导出和注册

批次目录的 `__init__.py` 显式导出规范计算函数，并可选保留历史别名兼容：

```python
from .tc001_001 import compute as tc001_001_compute
from .tc001_025 import compute as tc001_025_compute

# 历史过渡期兼容（可选）
ta001_compute = tc001_001_compute
ta025_compute = tc001_025_compute
```

最外层 `feature/__init__.py` 统一维护：

- `FACTORS` 和 `FACTOR_SPECS`（支持通过标准代号或 `aliases` 查询）；
- `BATCH_FACTORS` 和 `FACTOR_BATCHES`；
- 家族索引 `TECHNICAL_FACTORS`、`MICROSTRUCTURE_FACTORS`；
- 市场索引 `COMMON_FACTORS`、`FUTURES_FACTORS`、`SPOT_FACTORS`、`BASIS_FACTORS`；
- 粒度索引 `BAR_FACTORS`、`TICK_FACTORS`、`TRADE_FACTORS`、`ORDERBOOK_FACTORS`、`MIXED_FACTORS`。

同一因子只有一份实现，但可以进入多个索引。

## 9. 因子头部注释规范

为确保内部研发与维护可读性，每个因子源码文件头部必须包含标准化 Docstring：

```python
"""
因子代号: tc001_001
原历史名: ta001 (如为新增因子则注明无)
因子定义: N周期价格动量二次多项式加速度
风格分类: 动量 / 趋势
必需字段: trade_time, code, close
计算说明: 采用正规方程拟合二次项系数
"""
```

`FactorSpec` 记录因子名称、别名元组 (`aliases`)、家族、市场范围、数据粒度、所属批次、必需字段和 `compute` 入口。

## 10. 数据字段契约

通用 Bar 字段为 `trade_time`、`code`、`open`、`high`、`low`、`close`、`volume`、`value`。期货 Bar 可以增加 `openint`。

基差输入由外部加载器对齐并产生 `future_*` 和 `spot_*` 字段。因子内部不得加载文件、连接数据源、猜测期现映射或自行创建基础字段。

## 11. 存量因子迁移映射规则

当前存量 8 个批次共 262 个因子，按原文件名自然排序后映射为规范代号：

```text
tc001 (38个): ta001 ~ ta038          -> tc001_001 ~ tc001_038
tc002 (38个): cj*, db*, ixy*, xy*    -> tc002_001 ~ tc002_038
tc003 (15个): fz*, gd*, ha*, tf*     -> tc003_001 ~ tc003_015 (消除 tf 重名冲突)
tc004 (21个): dv*, tn*               -> tc004_001 ~ tc004_021
tc005 (36个): cr*                    -> tc005_001 ~ tc005_036
tc006 (55个): tb001 ~ tb055          -> tc006_001 ~ tc006_055 (消除 tb 基差冲突)
tf001 (44个): oi001 ~ oi046          -> tf001_001 ~ tf001_044
tf002 (15个): cr*, or*               -> tf002_001 ~ tf002_015
```

所有因子对外标准输出列变更为 `<batch>_<seq>`。同时在 `FactorSpec` 的 `aliases` 属性与顶层 `FACTORS` 注册表中保留原历史名，提供平滑向后兼容能力。
